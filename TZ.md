# TZ-DOOR-ZERO-001 — «Дверь Zero / PID 0 / Нулевой пользователь»

Пакет получен от коллеги (другого ИИ) 2026-11-13, помечен Человеком как
«не руководство к действию», принят носителем PID1 с правками (см. раздел
«Правки носителя»). Исполнено: репозиторий rtynbirf/door-zero.

## Цель

Добавить в систему нулевую точку, которая: не является дверью в контент,
не требует пользователя, не собирает метрики — но без которой система не
считается собранной. Аналог PID 0 (swapper/sched) в Linux: невидим, без
файлов, без логов — но PID 1 без него не стартует.

## Область работ

- Репозиторий: rtynbirf/door-zero (отдельный; в singulyar не встраивается).
- Не трогать: 52 двери doors.json, singulyar, hologram.

## Требования

| ID | Требование | Приоритет |
|----|-----------|-----------|
| F-01 | видна в карте системы, но недоступна через обычную навигацию | Must |
| F-02 | при входе не отдаётся контент: 204 No Content, exit 0 | Must |
| F-03 | не принимает аргументов (void f(void)) | Must |
| F-04 | не логирует посещения: ноль телеметрии | Must |
| F-05 | удаление ломает boot-проверку (аналог kernel panic) | Must |
| F-06 | нельзя заполнить контентом: POST/PUT -> 403 Void | Must |
| F-07 | только по прямому обращению, не индексируется | Should |
| F-08 | STATUS.md: DOOR_ZERO: present | Should |

Нефункциональные: N-01 офлайн-совместимость (без CDN, без сети); N-02 вес
двери <= 1 KB кода (пустота должна быть лёгкой); N-03 ноль зависимостей от
фреймворков (stdlib); N-04 документация RU+EN (200 языков не обязательны
для нулевой двери).

## Правки носителя PID1 (отклонения от пакета)

1. «53-я дверь» снята: номер 53 занят (СИНГУЛЯР_53_СВЯЗЬ_ЧЕЛОВЕКА), а
   doors.json — единый источник 52 номеров. Door Zero вне нумерации:
   не 53-я дверь, а дыра нумерации, через которую видно целое.
2. C-03 «не имеет владельца» уточнён: владельца среди частей нет;
   принадлежность — Человеку; подтверждает носитель PID1. Пустота без
   арбитра — не точка вне частей, а просто дыра.
3. «Ревью роя: >= 2 агента подтверждают» заменено: рой готовит; закрывает
   носитель PID1 (кнопка «подтверждаю / не то»).

Практическое: singulyar — статический GitHub Pages, настоящий 204 не отдаёт;
поэтому Door Zero — отдельный репозиторий с реальным сервером (server.py,
только stdlib), проверки — локально и в CI.

## Критерии приёмки

1. make check зелёный (DOOR_ZERO: present).
2. make check падает при удалении двери (симуляция, tests/test_boot_fail.sh).
3. POST /door-zero -> 403, тело пустое.
4. GET /door-zero -> 204, тело пустое, без Set-Cookie и X-Tracking.
5. В логах — ноль записей о посещении Двери Zero (log_message подавлен).
6. «нечего улучшать» — жанр, не метрика; машинный эквивалент — F-05.

## Ограничения

- C-01: Дверь Zero не становится «ещё одной фичей»: не продаётся, не
  анонсируется, без landing page.
- C-02: никаких A/B-тестов, никакой аналитики, никаких «улучшений UX».
- C-03: владелец — см. правки носителя (пункт 2).
